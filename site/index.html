为什么会扣得更快Why it uses more

Codex 每发一条消息，都会把当前对话里的内容一起交给模型。默认窗口较小，对话快满时 Codex 会自动压缩旧内容；窗口开大后，压缩来得更晚，每条消息带上的内容更多，所以每条消息消耗的额度也更多。Every message Codex sends includes the conversation so far. With the default window, Codex compacts older content once the conversation nears the limit. With a bigger window, compaction happens later, each message carries more, and each message uses more.

值不值得开？优点和代价Is it worth it? Pros and costs

按你的使用场景来取舍。Decide based on how you work.

优点Pros
  • 一次能读进更大的代码库和更多文档，不用反复喂资料
  • Read a bigger codebase and more docs at once, without re-feeding material
  • 长任务中途不容易触发自动压缩，前面的细节和决定不容易丢
  • Long tasks hit auto-compaction later, so earlier details and decisions are less likely to be lost
  • 跨很多文件的重构、排查问题时，AI 前后更连贯
  • More consistent work across many files, such as large refactors or debugging
代价Costs
  • 对话越长，每条消息越贵，订阅额度更快用完
  • Longer conversations make every message cost more; your subscription limit runs out sooner
  • 用 API Key 时，单次超过 272K 整次加价，费用可能翻倍
  • With an API key, requests over 272K are billed at a higher rate for the whole request
  • 要处理的内容越多，回复通常越慢
  • More content to process usually means slower replies
  • 旧内容一直带着，AI 可能被早先无关的信息干扰
  • Old content stays in, which can distract the AI with earlier, unrelated details
